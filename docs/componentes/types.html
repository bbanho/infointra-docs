types.ts — Contratos de Dados ​

Arquivo: src/types.ts · Símbolos codegraph: 14 · Licença: Apache-2.0

Papel ​

Fonte única de verdade para os contratos de dados — usado por todas as camadas (UI, Dexie, Supabase). Tipagem estrita em todo o projeto.

Order (núcleo do negócio) ​

export type PaymentMethod =
  | 'PIX' | 'CARTAO_CREDITO' | 'CARTAO_DEBITO'
  | 'BOLETO_30' | 'BOLETO_30_60_90' | 'FATURADO_ERP';

export type SyncStatus =
  | 'pendente_sync' | 'sincronizando' | 'sincronizado' | 'erro_sync';

export interface Order {
  codigoPedido: string;         // ex: "PED-2026-0842"
  vendedorId: string;
  clientId: number;
  itens: OrderItem[];
  formaPagamento: PaymentMethod;
  statusSync: SyncStatus;
  assinaturaBase64?: string;    // assinatura digital em canvas

  xmlGerado?: string;           // XML padrão ERP

  chaveNfe?: string;            // 44 dígitos SEFAZ
  protocoloNfe?: string;
  cupomFiscalNumero?: string;
  dataEmissaoFiscal?: string;
}

Observações de engenharia ​

  • IDs numéricos autoincrementados (id?: number) no cliente; o Supabase usa BIGINT IDENTITY — mapeamento direto.
  • SyncLogType com fallback string permite novos tipos de log sem quebrar o contrato.
  • OrderItem.id: string (UUID local) — itens são identificados de forma estável antes do sync.
