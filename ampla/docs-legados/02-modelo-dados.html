02 — Modelo de Dados & Supabase ​

Documento original

Conteúdo integral preservado de docs/02-modelo-de-dados-e-supabase.md. Parte da wiki para manter a rastreabilidade com a documentação histórica do projeto.

2.1 Visão Geral da Camada Cloud Supabase ​

O Supabase é utilizado como backend relacional Serverless, provendo:

  • Banco de dados PostgreSQL 15+ totalmente relacional;
  • API REST auto-gerada instantânea (PostgREST);
  • Inscrições em tempo real (WebSockets / Realtime);
  • Segurança por RLS (Row Level Security).

2.2 Script DDL de Criação do Banco de Dados PostgreSQL ​

O script a seguir (disponível para exportação direta pela interface do aplicativo em src/utils/supabaseAndFiscal.ts) cria a estrutura relacional completa:

sql
-- ============================================================================
-- SCRIPT DE CRIAÇÃO DE TABELAS - AMPLA VENDAS ERP (SUPABASE / POSTGRESQL)
-- ============================================================================

-- 1. TABELA DE CLIENTES
CREATE TABLE IF NOT EXISTS public.clientes (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    codigo_cliente VARCHAR(50) UNIQUE,
    nome VARCHAR(255) NOT NULL,
    nome_fantasia VARCHAR(255),
    cpf_cnpj VARCHAR(20) NOT NULL UNIQUE,
    ie VARCHAR(30),
    email VARCHAR(150),
    telefone VARCHAR(30),
    endereco VARCHAR(255),
    numero VARCHAR(20),
    bairro VARCHAR(100),
    cidade VARCHAR(100) NOT NULL,
    uf VARCHAR(2) NOT NULL,
    cep VARCHAR(10),
    limite_credito NUMERIC(15, 2) DEFAULT 0.00,
    saldo_devedor NUMERIC(15, 2) DEFAULT 0.00,
    status VARCHAR(20) DEFAULT 'ATIVO',
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 2. TABELA DE PRODUTOS E SERVIÇOS
CREATE TABLE IF NOT EXISTS public.produtos (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    sku VARCHAR(50) NOT NULL UNIQUE,
    nome VARCHAR(255) NOT NULL,
    descricao TEXT,
    categoria VARCHAR(100) NOT NULL,
    is_service BOOLEAN DEFAULT FALSE,
    unidade VARCHAR(10) DEFAULT 'UN',
    preco_base NUMERIC(15, 2) NOT NULL,
    preco_minimo NUMERIC(15, 2) NOT NULL,
    custo_unitario NUMERIC(15, 2) DEFAULT 0.00,
    estoque_atual NUMERIC(15, 3) DEFAULT 0.000,
    ncm VARCHAR(12) DEFAULT '8471.50.10',
    status VARCHAR(20) DEFAULT 'DISPONIVEL',
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 3. TABELA DE CONDIÇÕES DE PAGAMENTO
CREATE TABLE IF NOT EXISTS public.condicoes_pagamento (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    codigo VARCHAR(30) NOT NULL UNIQUE,
    descricao VARCHAR(150) NOT NULL,
    forma_pagamento VARCHAR(50) NOT NULL,
    parcelas INT DEFAULT 1,
    desconto_percentual NUMERIC(5, 2) DEFAULT 0.00,
    ativo BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 4. TABELA MESTRE DE PEDIDOS
CREATE TABLE IF NOT EXISTS public.pedidos (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    codigo_pedido VARCHAR(50) NOT NULL UNIQUE,
    data_criacao TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    vendedor_id VARCHAR(50) NOT NULL,
    vendedor_nome VARCHAR(150) NOT NULL,
    cliente_id BIGINT REFERENCES public.clientes(id),
    cliente_nome VARCHAR(255) NOT NULL,
    cliente_cpf_cnpj VARCHAR(20) NOT NULL,
    cliente_cidade VARCHAR(100),
    cliente_uf VARCHAR(2),
    subtotal NUMERIC(15, 2) NOT NULL,
    desconto_geral_valor NUMERIC(15, 2) DEFAULT 0.00,
    total NUMERIC(15, 2) NOT NULL,
    forma_pagamento VARCHAR(50) NOT NULL,
    parcelas INT DEFAULT 1,
    condicao_pagamento VARCHAR(150),
    status_sync VARCHAR(30) DEFAULT 'sincronizado',
    status_fiscal VARCHAR(30) DEFAULT 'PENDENTE',
    chave_nfe VARCHAR(44),
    protocolo_nfe VARCHAR(50),
    cupom_fiscal_numero VARCHAR(20),
    observacoes_pedido TEXT,
    xml_gerado TEXT,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 5. TABELA RELACIONAL DE ITENS DO PEDIDO (FOREIGN KEY + CASCADE)
CREATE TABLE IF NOT EXISTS public.pedido_itens (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    pedido_id BIGINT NOT NULL REFERENCES public.pedidos(id) ON DELETE CASCADE,
    produto_id VARCHAR(50),
    sku VARCHAR(50) NOT NULL,
    nome VARCHAR(255) NOT NULL,
    is_service BOOLEAN DEFAULT FALSE,
    unidade VARCHAR(10) DEFAULT 'UN',
    preco_unitario NUMERIC(15, 2) NOT NULL,
    quantidade NUMERIC(15, 3) NOT NULL,
    desconto_percentual NUMERIC(5, 2) DEFAULT 0.00,
    desconto_valor NUMERIC(15, 2) DEFAULT 0.00,
    subtotal NUMERIC(15, 2) NOT NULL,
    observacao TEXT,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- ÍNDICES DE PERFORMANCE PARA MÁXIMA VELOCIDADE NAS CONSULTAS
CREATE INDEX IF NOT EXISTS idx_pedidos_codigo ON public.pedidos(codigo_pedido);
CREATE INDEX IF NOT EXISTS idx_pedidos_vendedor ON public.pedidos(vendedor_id);
CREATE INDEX IF NOT EXISTS idx_pedido_itens_pedido_id ON public.pedido_itens(pedido_id);
CREATE INDEX IF NOT EXISTS idx_clientes_cpf_cnpj ON public.clientes(cpf_cnpj);
CREATE INDEX IF NOT EXISTS idx_produtos_sku ON public.produtos(sku);

2.3 Políticas de Segurança RLS (Row Level Security) ​

Para isolar os pedidos de cada vendedor no Supabase:

sql
-- Habilita RLS na tabela de pedidos
ALTER TABLE public.pedidos ENABLE ROW LEVEL SECURITY;

-- Política: Vendedor só lê e grava seus próprios pedidos
CREATE POLICY "Vendedor acessa apenas seus pedidos"
ON public.pedidos
FOR ALL
USING (vendedor_id = auth.uid()::text);

2.4 Integração Frontend via SDK (src/lib/supabase.ts) ​

A conexão com o Supabase é realizada diretamente pelo navegador através do cliente oficial @supabase/supabase-js, pré-configurado no sistema com fallback para credenciais salvas no armazenamento local.

typescript
import { createClient } from '@supabase/supabase-js';

export function getSupabaseClient() {
  const { url, anonKey } = getSupabaseConfig();
  if (!url || !anonKey) return null;
  return createClient(url, anonKey);
}
