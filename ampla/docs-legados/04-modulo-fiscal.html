04 — Módulo Fiscal (NF-e/NFC-e) ​

Documento original

4.1 Requisitos Legais e Legislação Fiscal Brasileira ​

A emissão de documentos fiscais eletrônicos no Brasil é regulamentada pela Secretaria da Receita Federal e pelas Secretarias de Fazenda Estaduais (SEFAZ).

O Ampla Vendas ERP suporta nativamente a geração, visualização e exportação de dois modelos principais de documentos fiscais:

  1. NF-e (Nota Fiscal Eletrônica Modelo 55): Utilizada em operações B2B (vendas corporativas, atacado e faturamento direto com DANFE impresso em formato A4).
  2. NFC-e (Nota Fiscal de Consumidor Eletrônica Modelo 65): Utilizada em vendas B2C e balcão (pronta entrega com fita térmica de 80mm).

4.2 Algoritmo de Geração da Chave de Acesso de 44 Dígitos ​

A Chave de Acesso é a identificação única do documento fiscal perante os servidores da SEFAZ. O código presente em src/utils/supabaseAndFiscal.ts implementa o cálculo oficial com o Módulo 11:

Exemplo de Chave de Acesso:
35 2608 18442981000192 55 001 000000842 1 10842918 4
── ──── ────────────── ── ─── ───────── ─ ──────── ─
│   │         │         │  │      │     │    │     └─ Dígito Verificador (Mod 11)
│   │         │         │  │      │     │    └────── Código Numérico Aleatório
│   │         │         │  │      │     └────────── Tipo de Emissão (1=Normal)
│   │         │         │  │      └──────────────── Número do Documento Fiscal
│   │         │         │  └─────────────────────── Série (001)
│   │         │         └────────────────────────── Modelo (55 = NF-e / 65 = NFC-e)
│   │         └──────────────────────────────────── CNPJ do Emitente
│   └────────────────────────────────────────────── Ano e Mês de Emissão (AA/MM)
└────────────────────────────────────────────────── Código da UF (35 = São Paulo)

Algoritmo do Dígito Verificador (Módulo 11) ​

typescript
export function generateNfeAccessKey(
  ufCode: string = '35',
  cnpj: string = '18442981000192',
  model: string = '55',
  series: string = '001',
  number: number = 842
): string {
  const date = new Date();
  const year = date.getFullYear().toString().slice(-2);
  const month = (date.getMonth() + 1).toString().padStart(2, '0');
  const docNumber = number.toString().padStart(9, '0');
  const tpEmis = '1'; // Normal
  const randomCode = Math.floor(10000000 + Math.random() * 90000000).toString();

  const rawKey = `${ufCode}${year}${month}${cnpj}${model}${series}${docNumber}${tpEmis}${randomCode}`;

  // Cálculo do Dígito Verificador (Módulo 11)
  let weight = 2;
  let sum = 0;
  for (let i = rawKey.length - 1; i >= 0; i--) {
    sum += parseInt(rawKey.charAt(i), 10) * weight;
    weight = weight === 9 ? 2 : weight + 1;
  }
  const remainder = sum % 11;
  const dv = remainder === 0 || remainder === 1 ? 0 : 11 - remainder;

  return `${rawKey}${dv}`;
}

4.3 Cálculo da Lei da Transparência Fiscal (IBPT ~18.45%) ​

Em conformidade com a Lei Federal nº 12.741/2012, o sistema calcula automaticamente a estimativa de tributos federais, estaduais e municipais incidentes sobre cada venda:

$$\text{Tributos Estimados} = \text{Valor Total do Pedido} \times 18,45%$$

Esse valor é exibido no rodapé do Cupom Fiscal NFC-e e no campo de Informações Complementares do DANFE A4.

4.5 Componentes Visuais e Suporte a Impressoras Térmicas ​

  • DanfeNfeModal.tsx: Modal responsivo com visualização A4 do DANFE Modelo 55 contendo código de barras da chave de acesso e áreas de canhoto de recebimento.
  • FiscalReceiptModal.tsx: Modal formatado com margem fixa de 80mm para impressão direta em impressoras térmicas como Bematech MP-4200 TH, Elgin i9, e Daruma DR800.
