Adaptadores para ERPs Legados ​

Problema ​

O Ampla Vendas ERP precisa integrar com ERPs corporativos distintos — SAP, TOTVS, Senior, Linx — cada um com API, schema e protocolo próprios. Acoplar o PWA diretamente a cada ERP quebraria a portabilidade e a simplicidade do cliente.

Solução: padrão Adapter via middleware ​

O PWA conversa com um único contrato canônico; o middleware traduz para cada ERP. Isso mantém:

  • Um payload único no front (o xmlGerado do pedido segue um schema próprio, http://www.amplavendas.eng.br/schema/erp/v2).
  • Adaptadores substituíveis — adicionar um ERP novo = novo adapter no middleware, zero mudança no front.
  • DLQ (Dead Letter Queue) para mensagens que falham após retries — nenhum pedido se perde.
  • Idempotência — o codigo_pedido único garante que reenvios não duplicam no ERP.

Payload canônico ​

O front já gera o XML de integração em lote (MainApp.tsx → handleExportAllXml):

xml
<LoteIntegracaoERP xmlns="http://www.amplavendas.eng.br/schema/erp/v2">
  <IdentificacaoOrigem>
    <Sistema>Ampla Vendas Pro - PWA Offline-First</Sistema>
    <Versao>2.4.0</Versao>
    <Representante>Bruno Silva (VEND-104)</Representante>
  </IdentificacaoOrigem>
  <Pedidos>
    <!-- um <Pedido> por pedido, gerado por generateOrderErpXml() -->
  </Pedidos>
</LoteIntegracaoERP>

Sincronização simulada no front ​

O ErpSyncCenter + handleSyncPendingOrders (MainApp.tsx:217) implementam o ciclo de sincronização com um REST simulado (800ms de latência) para demonstrar o fluxo de outbox:

  1. Filtra pedidos com statusSync === 'pendente_sync'.
  2. Simula a chamada à API ERP.
  3. Marca como sincronizado com dataSincronizacao.
  4. Registra ENVIO_PEDIDOS no syncLogs.

A integração real substitui a simulação pela chamada ao middleware Adapter.
