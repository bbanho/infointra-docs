Módulo Fiscal (NF-e / NFC-e / SAT) ​

O motor fiscal roda no cliente — sem servidor — para que a emissão continue funcionando offline. São dois documentos:

1. DANFE — NF-e Modelo 55 (A4) ​

Componente: DanfeNfeModal.tsx · Utils: src/utils/supabaseAndFiscal.ts

  • Layout oficial DANFE em A4 com CSS @media print.
  • Chave de acesso de 44 dígitos padrão SEFAZ SP (gerada por generateNfeAccessKey()).
  • Protocolo de autorização de uso (gerado e armazenado em order.protocoloNfe).
  • Detalhamento de impostos: base ICMS, ICMS 18%, PIS/COFINS, Simples Nacional.
  • Tabela de itens com NCM (ex: 8471.50.10), CST (0102), CFOP (5102) e alíquotas.
  • Ações: Imprimir/Salvar PDF e Download do XML v4.00.

2. Cupom Fiscal — NFC-e / SAT (80mm) ​

Componente: FiscalReceiptModal.tsx

  • Formato de fita térmica 80mm com layout corporativo.
  • Tributos aproximados (IBPT ~18,45%) conforme a Lei da Transparência Fiscal.
  • QR Code e código de barras para consulta pública na SEFAZ.
  • Botão Imprimir com @media print otimizado para impressoras térmicas (Bematech, Elgin, Daruma).

Fluxo de emissão ​

Geração da chave de acesso (44 dígitos) ​

Em src/utils/supabaseAndFiscal.ts — generateNfeAccessKey():

  • Composição: UF + data de emissão + CNPJ + modelo (55) + série + número + tipo de emissão + código numérico + DV (dígito verificador).
  • O DV é calculado pelo algoritmo módulo 11 (pesos 2–9), padrão SEFAZ.

Estado fiscal no pedido ​

O campo statusFiscal do pedido (Order.type.ts) segue o ciclo:

PENDENTE → NFE_EMITIDA  (DANFE emitida, chave + protocolo gravados)
PENDENTE → CUPOM_EMITIDO (cupom emitido, número gravado)

A atualização é feita por handleUpdateOrderFiscal() no MainApp.tsx, que também registra auditoria (EMISSAO_FISCAL).
