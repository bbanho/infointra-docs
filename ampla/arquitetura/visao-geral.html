Visão Geral da Arquitetura ​

Ampla Vendas ERP — PWA Offline-First para força de vendas, com persistência local (IndexedDB), sincronização assíncrona para nuvem (Supabase) e integração com ERPs legados via padrão Adapter.

Princípios de arquitetura ​

PrincípioAplicação no projeto
Offline-FirstTodas as operações de venda (pedido, cliente, catálogo) gravam primeiro no IndexedDB via Dexie; a nuvem é um destino de sincronização, não um requisito de operação.
Hybrid CloudSupabase (PostgreSQL + PostgREST) como backend gerenciado; integração com ERPs legados por microserviço middleware.
Tipagem estritaTodos os contratos de dados centralizados em src/types.ts — entidades, enums e estados fiscais tipados.
Separação de responsabilidadesdb/ (persistência), lib/ (cliente cloud), stores/ (estado), utils/ (formatação e fiscal), components/ (UI).
PragmatismoStack estável e escalável (React + Dexie + Supabase) em vez de modismos; engenharia guiada por negócio (100% disponibilidade em campo).

Decisões de engenharia (resumo) ​

  • Dexie.js + IndexedDB: documento único no browser — Order carrega os itens embutidos (itens: OrderItem[]); cabeçalho e itens são gravados num único db.orders.add() (atomicidade por documento, sem transação multi-tabela).
  • Zustand para estado global leve (usuário, flag de sync) — sem prop drilling.
  • useLiveQuery (dexie-react-hooks): UI reativa ao banco local sem estado duplicado.
  • Supabase como nuvem relacional: PostgREST + RLS; credenciais configuráveis no front (localStorage) com fallback de env vars.
  • Motor fiscal no cliente: geração de chave de acesso, protocolo e XML v4.00 sem servidor — resiliência total em campo.
