Agendamento Universal — Design Inicial ​

Status: ACEITA — fase de design (sem código) · Documento-pivô da sessão Norte: "O melhor e simples sistema de agendamento possível para integrar no ecossistema ERP genérico."

1. Visão (1 página) ​

Um sistema de agendamento completo, simples e genérico que vive dentro do ecossistema ERP: traduz tipos de dados em full duplex com o ERP e sistemas adjacentes, com o primeiro cliente sendo clínicas médicas (consultas).

Princípios:

  1. Simples primeiro — qualquer complexidade (pipeline, canônico, LLM) só entra se pagar o próprio custo.
  2. Integrado, não ilha — o sistema é um componente do ecossistema; fala com o ERP nos dois sentidos.
  3. Vertical-agnóstico — nada de setor no núcleo; setor entra por adaptador.
  4. Regras em português, LLM como componente — regras de negócio declaradas em pt-BR, interpretadas por LLM (design-time), fora do domínio puro.

2. Arquitetura (hexagonal) ​

DecisãoEscolha
FormatoHexagonal: domínio puro + portas + adaptadores bijetivos
Casos de usoSteps tipados, cada um testável isoladamente
ConcorrênciaUoW + lock no reserva de slot (dois pacientes, mesmo horário)
CanônicoFHIR-inspired simplificado: Patient, Practitioner, Schedule, Slot, Appointment
LLMDesign-time (regras em pt-BR → configuração determinística); runtime só p/ casos de borda
